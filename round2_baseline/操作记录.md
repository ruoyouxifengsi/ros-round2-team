# 第二轮控制 baseline：操作记录

## 2026-11-11 稳定验收后的可选提速配置

本节优先于下方历史记录。原质心和低质心车模均保留；速度配置另分 `stable`（默认）与 `fast`（可选）。本次提速整轮测试只针对低质心、机械臂收起、不识别图像的条件。稳定版完整提交另存标签 `stable-multilayout-v1`，可在另一份克隆中检出复现。

### 方法选择与代码实现

小车需要“空旷直段更快、急转时收速、接近停车点减速”。此次沿用现有 [TEB 时间优化局部规划器](https://github.com/rst-tu-dortmund/teb_local_planner)，增加转弯速度调节和按剩余距离减速的直线停车控制。

调研对照包括 [Nav2 MPPI](https://github.com/ros-navigation/navigation2/blob/main/nav2_mppi_controller/README.md)、[Regulated Pure Pursuit](https://arxiv.org/abs/2305.20026) 和2025年的 [Multi-Modal MPPI](https://arxiv.org/abs/2508.21364)。MPPI通过采样多条未来轨迹选择控制，是先进的候选方向；现成Nav2实现属于ROS 2，本项目官方环境为ROS 1 Noetic，直接迁移需要重新验证接口、模型和整条比赛链路。论文中的汽车动力学也不能直接套到本车。结合现有稳定基础，本次选择借鉴曲率调速思路并保留TEB，未实现MPPI或完整RPP，也不宣称这是业内唯一最优算法。

| 项目 | stable | fast |
|---|---:|---:|
| TEB前进速度上限 | 0.25 m/s | 0.40 m/s |
| TEB后退速度上限 | 0.12 m/s | 0.18 m/s |
| TEB横向速度上限 | 0.15 m/s | 0.22 m/s |
| 保护器平移速度上限 | 0.30 m/s | 0.45 m/s |
| QR退出、终点直行速度上限 | 0.08 m/s | 0.18 m/s |
| 平移加速度上限 | 0.5 m/s² | 0.5 m/s² |

- `config/speed_fast.yaml` 覆盖TEB速度；`launch/control.launch` 按 `speed_profile` 加载配置，默认stable。
- `scripts/attitude_guard.py` 用指令平移速度×角速度作为转弯强度近似；超过0.12时同比缩小平移与角速度，保留目标转弯比例。这是指令侧的经验调节，后续加速度限制、偏航反馈和轮胎滑移仍会影响实际运动，不能声称实际侧向加速度严格不超过0.12 m/s²。
- `scripts/control.py` 提高两段直线移动上限，并随剩余距离减速；原有整车轮廓预测碰撞检查、停车容差、18个目标及超时不变。3°暂停、8°故障姿态阈值不变。

同一套提速代码连续完成种子1、2、3、42，每种一次，均通过18/18目标以及QR、终点完整车身入框与停稳检查。与下方稳定验收对应布局作对照，未按不同种子单独调参数。

| 1 | 541.43 | 417.34 | 22.92% | 164.291 | 124.828 | 0.381° |

四轮通过率4/4，卡住0次、姿态保护触发0次；最大倾角由稳定版最高0.299°增加至0.456°，未观察到前倾翻倒或侧翻。五桶位移审计完整，最大水平位移均小于4×10⁻¹¹米，未发现可测移动。位移不是碰撞接触计数，5毫米筛查阈值不是官方允许碰桶幅度。

种子3的 `bend5_approach` 用时约16.75仿真秒，稳定版约5.6秒，抵消了其他路段部分收益；日志和轨迹表现为到点收敛绕行，没有达到无进展超时。它说明提高速度上限不保证每段都快。四种已测试布局各一次，样本有限且不是全新盲测，不能推断所有现场布局的成功率。此次没有失败整轮需要排除；全部四轮数据保留。

### 发现的问题及修复

1. 原控制方案在种子1整轮运行时，QR退出后约 `(-0.221,0.246)` 处转身无进展，28秒后失败。失败地图回放显示中间转角与占用格相交；单独新建地图的局部复现却能通过，说明不能用单段成功替代整轮验证。入口目标由 `(-0.25,0.25)` 上移至 `(-0.25,0.35)`，保留碰撞检查。
2. 只移动入口的后半程诊断中，原避障方案推动一个桶约0.110米，并在约 `(-1.467,1.398)` 附近卡住。新增 `scripts/cone_obstacles.py`，由实时 `/nav_scan` 检测小轮廓，多帧确认后补足桶底座，不从种子、布景日志或Gazebo真值取得桶坐标。
3. 补底座后没有再推桶，但旧出口目标 `(-1.75,2.05)` 离允许生成的最高一排桶过近，90秒和150秒测试都未到达。出口改为 `(-1.75,2.20)` 后通过；穿桶阶段保留150秒预算，总540秒及无进展28秒保护不变。
4. 后半程诊断中，终点处已在框内但横向误差超过原1.5厘米到点容差，出现无进展。终点容差改为2.5厘米，并仍按实际完整车身入框和停稳验收。最终四轮均通过，不能只看目标返回成功。
5. 修正测试器：`--low-com` 与单段调试同时使用时也保持低质心模型，不再重新加载官方原版。

这些失败均保留于 `evidence/multilayout_20261111`，其中 `multi_v1_s1` 是旧方案整轮失败；`entry_*`、`cone_tail_*` 是局部诊断，**不混入最终4/4**。原方案第一次新增布局整轮测试为0/1，不能忽略该失败。详细本地日志在被Git忽略的 `evidence/local_*` 下，GitHub只保存紧凑证据。

### 新避障模块如何工作

`/scan → 姿态保护 → /nav_scan → 激光障碍层`；同时 `/nav_scan → cone_obstacles → /cone_footprints → 独立底座障碍层`。TEB读取合成地图，选择路线。

检测器将实测轮廓中心与**第二轮官方允许格点**匹配，误差须小于10厘米，至少三次观测确认；它并不知道哪些格点实际放桶。底座按15厘米半径补点，不由激光清空，避免底座低于扫描面而被擦掉。新一轮重启场景与导航，清空检测记忆。它假设比赛锥桶静止，且按官方格点生成；不适用于任意自由复制摆桶、移动障碍或未经修改的第一轮场地。不能将“采用已知格点”误解为“提前读取布局”。

|---|---|
| `MOVING` | 正在执行某个目标 |
| `ARRIVED` | 该阶段完成，并确认停稳 |
| `IMAGE_SKIPPED` | 本版跳过图像任务 |
| `FAILED` | 本次失败，查看 detail 和日志 |
| `CONTROL_ROUTE_DONE` | 移动控制流程结束，仍需检查入框证据；不代表完整比赛完赛 |

只在开发测试或裁判允许截车后取消：

```bash
rosservice call /nav_start "data: false"
```

等待车辆停止，再在启动终端按 Ctrl+C。官方计时器的 Stop 不等于取消导航。再次发车需要重新启动场景回到起点，不从终点直接启动下一轮；不要用 `wsl --shutdown` 关闭其他项目。

## 4. 一条命令复现整轮测试

先关闭手动启动的本任务仿真，再运行：

```bash
source ~/round2_baseline_ws/devel/setup.bash
python3 /mnt/d/ros智能车/round2_baseline/scripts/run_trial.py \
  /mnt/d/ros智能车/round2_baseline/evidence/my_trial \
  --cones --seed 42 --timer
```

输出目录必须是新目录。它会启动官方场景、运行两份官方布景程序、通过未修改的官方 Draw 控件发车，并保存全过程。过程中不要人工发速度或修改参数。

- `--seed 42` 只用于练习复现，不会把桶的位置传给控制程序；正式比赛不使用固定种子。
- 不加 `--timer` 是服务接口开发测试，不算官方计时器验证。
- 所有 `--debug-...` 参数只用于诊断，结果明确标记 DEBUG，不能算整轮验收。
- 测试器使用独立端口和互斥锁，只清理自己启动的进程组，不关闭整个 WSL。

测试结束后检查：

```bash
python3 /mnt/d/ros智能车/round2_baseline/scripts/analyze_trial.py \
  /mnt/d/ros智能车/round2_baseline/evidence/my_trial
python3 /mnt/d/ros智能车/round2_baseline/scripts/plot_trial.py \

```

重点看 `analysis.json` 中的 `control_baseline_pass`。它要求完整目标顺序、QR/终点车身入区、终点停稳、官方发车、随机场景及发车后时间检查均通过，并排除 DEBUG 和人工调整过的记录。

| 证据 | 用途 |
|---|---|
| `result.json` | 阶段事件、终态、实际墙钟时间 |
| `analysis.json` | 到位位置、完整车身边界、停稳和整轮验收 |
| `trajectory.png` | 根据激光和里程计绘制的路线 |
| `timer/timer.json` | 官方 Draw 次数及计时器状态 |

## 5. baseline 是怎样完成的

控制链：

```text
官方 Draw → /nav_start → control.py
                         ├─ 普通路线、QR停靠：move_base + TEB
                         └─ QR退出、终点：里程计直线跟踪 + 地图车身碰撞检查
                                      ↓ /nav_cmd_vel
                               姿态保护 + 转向反馈
                                      ↓ /cmd_vel
                                   官方车模

/scan + /odom → 倾斜扫描门控 → /nav_scan → 导航地图
```

导航读取正常传感器与导航接口，不读取 Gazebo 模型位置，也不读取随机生成日志中的桶坐标或类别。官方计时器和布景程序自身使用的 Gazebo 接口保持原样。

主要修复如下：

| 问题 | 最终处理 |
|---|---|
| 第一轮路线和地图不能直接适用第二轮 | 依据第二轮场地重新设置路线，使用激光滚动地图；QR从开口侧进出，返程走下方通道 |
| 矩形车身轮廓在窄弯中过于保守 | 从官方 URDF 全部碰撞网格测量收臂轮廓，使用包住真实车身并留余量的八边形；未缩放车模 |
| 有转向指令却几乎不转 | 用里程计角速度进行有界比例、积分修正；输出不超过0.65弧度/秒，停止或保护触发时清零积分 |
| DWA在窄弯到点转向失败 | 按赛事教程改用TEB，并给第五弯增加直行到位点 |
| QR附近通用轨迹反复转身 | QR以低速精确进入；退出改为有地图碰撞检查的固定直线倒车 |
| 同一避障间距不适合全部阶段 | 普通窄通道期望间距0.02米；穿桶、物块、返程用0.08米；这不是实际净空保证 |
| 开阔过渡点因厘米级超调卡住 | 锥桶出口、物块前使用5厘米到位容差；其他过渡点通常3厘米 |
| 返程目标与较大避障间距冲突 | 目标移到通道内更宽松的 `(-0.70,1.20)` |
| 终点规划和预计轨迹靠近前墙 | 低速直线停车，目标为 `(-0.25,2.20)`；以完整车身入框和停稳验收 |

直线控制最大速度0.08米/秒。它检查未来约1秒、截至预计停车位置并留少量制动余量的车身范围；车身多边形与障碍方格采用精确相交检查，避免用外接圆近似方格造成误阻塞。障碍、未知格和地图越界都会阻止继续平移。QR退出到位容差3厘米，终点直线停车容差1.5厘米，最终仍按实际车身入框检查。局部地图持续发送完整更新。数据过期、偏航过大、无进展或超时均会失败停车。

TEB的代价地图碰撞检查、完整车身轮廓、姿态保护一直保留。保护在约3°倾斜时暂停，严重倾斜锁定故障。阶段通常最多90秒，总运行保护默认540秒；这些开发保护不替代裁判判定。

相关一手资料：

- [ROS Noetic 障碍评分源码](https://github.com/ros-planning/navigation/blob/noetic-devel/base_local_planner/src/obstacle_cost_function.cpp)：DWA的负分包含车身碰撞检查失败。
- [TEB 官方参数定义](https://github.com/rst-tu-dortmund/teb_local_planner/blob/noetic-devel/cfg/TebLocalPlannerReconfigure.cfg)：轨迹、避障和运动约束设置。

## 6. 自检、修改和双人分工

在加载ROS环境的WSL中：

```bash
cd /mnt/d/ros智能车/round2_baseline

```

保护自检覆盖启动、速度变化限制、过期数据、冻结时钟、倾斜、扫描门控及转向反馈。直线控制自检覆盖车身内障碍、格子边缘、旋转、未知格、地图边界，以及前进/倒退收敛。文件检查核对官方文件与收臂轮廓包络。

修改路线时，先理解朝向：0朝右、1.57朝上、3.14朝左、-1.57朝下。不要把固定目标放在可能生成锥桶的格点上。每次只改一个明确问题，输出到新证据目录；修改机械臂姿态后必须重新检查车身轮廓。

| 人员 | 负责内容 | 交付检查 |
|---|---|---|
| A：控制与复现 | 维护路线、避障、停车；用不同官方随机布局做复测 | 目标顺序、轨迹、入框和耗时 |
| B：图像与规则 | QR读取、对应物块识别、指定格式播报；本地模型和结果留存 | 使用现场相机结果，接入两个 `IMAGE_SKIPPED` 占位处 |

B按本文从零复现A的控制版本，A核对B的识别数据来源。联调时将图像占位替换为“等待识别完成或超时失败”，然后重新测试全程和总时间。

较早的尝试、失败与中间假设保留在 `evidence/development_notes.txt` 及各测试目录中；它们是历史证据，不是当前操作步骤。
