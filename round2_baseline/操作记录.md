# 第二轮控制 baseline：操作记录

## 2026-11-12 锥桶入口短转向与停靠提速

在上一版连续过弯基础上，新增可选 `--efficient-approach`。旧的完整版本保留在 `continuous-before-docking-v2` 标签，`main` 和官方原车模继续保留。省略该选项即可使用此前的入口及停靠逻辑。

### 原因与改法

上一版种子 42、2 在锥桶入口实际累计转了约 267°、257°，虽然最终方向正确，却绕了远路；种子 1 约转 91°，没有同样问题。检查导航输出确认，大转圈的方向来自局部规划器，姿态保护没有把方向反过来。

新逻辑在二维码退出后，先用闭环短距离横移到达入口位置，再按最短方向转身。这段横移仅允许在距入口 25 厘米以内启动，保持原朝向，合速度上限 0.12 m/s，按实时障碍地图预测检查车身未来轨迹；抵达 1.5 厘米内后停止。每次转向指令前也检查整个剩余转动扫过的车身范围；障碍或未知区域挡住就安全失败，不强行穿过。两步仍经姿态保护器下发速度，不读取仿真真值控制小车。转向结束要求角度误差小于 0.12 rad（比该普通入口原有的 0.25 rad 更严格），停稳后再次核对位置未离开原来的 3 厘米容差，才报告入口到达。QR 的精确朝向容差不受影响，穿锥桶路段仍由 TEB 规划。

| 路段 | 此前上限 | 新选项开启且为 fast/sprint 时 |
|---|---:|---|
| 二维码最后接近 | 全段 0.10 m/s | 前段 0.20 m/s，距目标不足 12 厘米恢复 0.10 m/s |
| 二维码直线退出 | 0.18 m/s | 0.22 m/s，接近目标按剩余距离减速 |
| 终点直线停靠 | 0.18 m/s | 0.28 m/s，接近目标按剩余距离减速 |

直线段增加横向误差纠正能力，允许小角度误差下边走边纠偏，偏角较大时才先转向。提速后预测轨迹的平移采样间距不超过约 1 厘米，保留完整车身碰撞检查。二维码位置容差 1 厘米、朝向容差 0.08 rad、退出 3 厘米及终点 2.5 厘米的位置容差保持原值。官方重力、步长、求解器、模型质量和惯性均未修改，低质心仍是已获准版本。

局部开发过程保留了一个性能反例：过于严格地要求“先原地对准再走”，使终点测试用时增加到 9.853 仿真秒，因此没有采用。改为行驶中纠偏后，同一起点的终点测试为 4.711 秒；二维码局部测试 4.036 秒。这些是调试起点的局部测试，不能算整轮通过。

入口最初“先转后移”的局部测试曾通过（5.451 秒、88.4°），但第一次整轮种子 42 在入口被安全检查拦停，接触和保护触发均为 0。离线回放当时地图发现：二维码退出位置附近的边界占据格，在约 57°～63° 转角扫到车身后角，移向入口 2.5 厘米后即可消除该冲突。因此改成“先到入口位置、后转身”，保留原碰撞检查。失败的整轮记录和地图快照一并归档，没有把它算进最终通过次数。协调器回归检查验证移动先于转身、且转身并停稳之后才报告到达。

第二次尝试先给 TEB 一个保持原朝向的入口目标，但 TEB 中间轨迹仍绕转，因此观察到问题后主动取消该轮，记录为开发中止，不算通过。随后将这段短横移改为上述带碰撞预测的控制。另一次局部命令漏加 `--debug-control`，实际仅测试了 TEB 目标，已明确排除出新控制验收；真正的控制局部验证必须同时传入 `--debug-control` 和 `--debug-stage cone_entry`。

修正后的入口控制局部复测：6.175 仿真秒，累计转角 83.20°，车桶接触 0、保护触发 0，停稳后位置检查通过。随后才固定代码进行三个布局的整轮验收。

在 WSL 的仓库根目录执行，每次换新的输出目录：

```bash

  round2_baseline/evidence/local_efficient_practice_01 \
  --low-com --cones --seed 42 --speed-profile sprint \
```

命令自动布景和发车；若要复制粘贴手工摆桶或自己点击 Draw，使用下方的手动流程，不要同时运行自动测试器。手动入口默认原车模，新增 `low_com:=true` 可加载已获准的低质心；三个控制选项本身不会切换车模。手工摆桶仍须遵守官方允许的格点布局。

只复核三种布局时，先按下方章节编译接触观察器，然后执行：

### 手动点击计时器发车

先关闭此前本项目的仿真。终端一（WSL Ubuntu 20.04）：

```bash
cd "/mnt/d/ros智能车/round2-team"
source ~/round2_team_ws/devel/setup.bash
export ROS_MASTER_URI=http://localhost:11311 GAZEBO_MASTER_URI=http://localhost:11345
roslaunch round2_baseline baseline.launch \
  timer:=true low_com:=true gui:=true \
  speed_profile:=sprint continuous_bends:=true efficient_approach:=true
```

这会打开 Gazebo 和官方计时器，小车等待手动发车；没有自动 Draw 驱动。终端二加载同一环境，再准备场景：

```bash
source ~/round2_team_ws/devel/setup.bash
export ROS_MASTER_URI=http://localhost:11311 GAZEBO_MASTER_URI=http://localhost:11345
rosrun car3 random_cones.py
rosrun car3 random_place.py
rostopic echo -n 1 /baseline/ready
```

若已手工摆好符合规则的锥桶，跳过 `random_cones.py`，避免被重新布景。等输出 `data: True` 后，在计时器填写组号，自己点击 **Draw**；不要另外调用 `/nav_start`。若输出 False，先等待模型和控制初始化，再查询一次。计时模式自动使用实际时间预算，不能同时启用仿真时间超时预算。

暂停练习时，计时器 Stop 仅停止计时，并不保证取消导航。需要取消控制可在终端二执行 `rosservice call /nav_start "data: false"`，停稳后在终端一 Ctrl+C。下一轮重新启动场景。

手动低质心入口只在原官方 launch 展开后覆盖本次 `robot_description` 参数，使用仓库内低质心模型；官方文件没有修改。参数检查确认低质心与原模型结构仅有已批准的质心 z 差异、默认仍是原版、计时模式为 wall，且只启动官方计时器、不启动自动测试器。此项检查没有运行仿真，不追加整轮测试。

## 2026-11-12 连续过弯与提速：三个布局验收通过

本次继续使用官方 Gazebo/ODE、官方物理参数和已获准的低质心模型，不再使用并行碰撞修改。按用户要求，最终只验证三个官方随机布局：42、1、2。

### 改了什么

此前每个弯道点都要停车、调整朝向，然后才发下一个目标。现在开启 `continuous_bends` 后，在普通弯道点 10 厘米以内就衔接下一段；TEB 在这些临时目标处不要求零终点速度，也不要求收敛到该点的指定朝向。路径始终经过实时障碍检查，没有按固定锥桶坐标盲走。

只对 `bend*` 普通路径点启用连续通过，且一段路线的最后一个点始终停稳。QR 入口、QR 停靠、退出、锥桶入口、物块、返回、终点入口和终点仍按原逻辑停稳，任务区容差不变。图像队友只能在 QR / 物块实际停稳后执行识别，不能用 `PASSED` 触发图像动作。

| 参数 | 原 fast | 新 sprint |
|---|---:|---:|
| 前进上限 | 0.40 m/s | 0.50 m/s |
| 倒车上限 | 0.18 m/s | 0.18 m/s |
| 侧向上限 | 0.22 m/s | 0.25 m/s |
| 规划角速度上限 | 0.50 rad/s | 0.60 rad/s |
| 平移加速度上限 | 0.50 m/s² | 0.65 m/s² |
| 保护器平移合速度上限 | 0.45 m/s | 0.55 m/s |
| 指令转弯强度调节参数 | 0.12 | 0.18 |

最后一项仍只是用“指令平移速度 × 指令角速度”调速的近似量，不是实际横向加速度的严格保证。倾斜暂停 3°、故障保护 8°、车身轮廓和碰撞检查均未放宽。

### 初学者复现步骤

1. 获取 `official/fast-control` 分支，按 README 完成 WSL / ROS 环境配置。已有本仓库且没有自己的未保存修改时，可 `git pull --ff-only` 更新。

```bash
  -o ~/round2_team_tools/contact_audit \
```

### 方法选择与代码实现

小车需要“空旷直段更快、急转时收速、接近停车点减速”。此次沿用现有 [TEB 时间优化局部规划器](https://github.com/rst-tu-dortmund/teb_local_planner)，增加转弯速度调节和按剩余距离减速的直线停车控制。

调研对照包括 [Nav2 MPPI](https://github.com/ros-navigation/navigation2/blob/main/nav2_mppi_controller/README.md)、[Regulated Pure Pursuit](https://arxiv.org/abs/2305.20026) 和2025年的 [Multi-Modal MPPI](https://arxiv.org/abs/2508.21364)。MPPI通过采样多条未来轨迹选择控制，是先进的候选方向；现成Nav2实现属于ROS 2，本项目官方环境为ROS 1 Noetic，直接迁移需要重新验证接口、模型和整条比赛链路。论文中的汽车动力学也不能直接套到本车。结合现有稳定基础，本次选择借鉴曲率调速思路并保留TEB，未实现MPPI或完整RPP，也不宣称这是业内唯一最优算法。

| 项目 | stable | fast |
|---|---:|---:|
| TEB前进速度上限 | 0.25 m/s | 0.40 m/s |
| TEB后退速度上限 | 0.12 m/s | 0.18 m/s |
| TEB横向速度上限 | 0.15 m/s | 0.22 m/s |
| 保护器平移速度上限 | 0.30 m/s | 0.45 m/s |
| QR退出、终点直行速度上限 | 0.08 m/s | 0.18 m/s |
| 平移加速度上限 | 0.5 m/s² | 0.5 m/s² |

- `config/speed_fast.yaml` 覆盖TEB速度；`launch/control.launch` 按 `speed_profile` 加载配置，默认stable。
- `scripts/attitude_guard.py` 用指令平移速度×角速度作为转弯强度近似；超过0.12时同比缩小平移与角速度，保留目标转弯比例。这是指令侧的经验调节，后续加速度限制、偏航反馈和轮胎滑移仍会影响实际运动，不能声称实际侧向加速度严格不超过0.12 m/s²。
- `scripts/control.py` 提高两段直线移动上限，并随剩余距离减速；原有整车轮廓预测碰撞检查、停车容差、18个目标及超时不变。3°暂停、8°故障姿态阈值不变。

### 新避障模块如何工作

`/scan → 姿态保护 → /nav_scan → 激光障碍层`；同时 `/nav_scan → cone_obstacles → /cone_footprints → 独立底座障碍层`。TEB读取合成地图，选择路线。

检测器将实测轮廓中心与**第二轮官方允许格点**匹配，误差须小于10厘米，至少三次观测确认；它并不知道哪些格点实际放桶。底座按15厘米半径补点，不由激光清空，避免底座低于扫描面而被擦掉。新一轮重启场景与导航，清空检测记忆。它假设比赛锥桶静止，且按官方格点生成；不适用于任意自由复制摆桶、移动障碍或未经修改的第一轮场地。不能将“采用已知格点”误解为“提前读取布局”。

## 5. baseline 是怎样完成的

控制链：

```text
官方 Draw → /nav_start → control.py
                         ├─ 普通路线、QR停靠：move_base + TEB
                         └─ QR退出、终点：里程计直线跟踪 + 地图车身碰撞检查
                                      ↓ /nav_cmd_vel
                               姿态保护 + 转向反馈
                                      ↓ /cmd_vel
                                   官方车模

/scan + /odom → 倾斜扫描门控 → /nav_scan → 导航地图
```

导航读取正常传感器与导航接口，不读取 Gazebo 模型位置，也不读取随机生成日志中的桶坐标或类别。官方计时器和布景程序自身使用的 Gazebo 接口保持原样。

主要修复如下：

| 问题 | 最终处理 |
|---|---|
| 第一轮路线和地图不能直接适用第二轮 | 依据第二轮场地重新设置路线，使用激光滚动地图；QR从开口侧进出，返程走下方通道 |
| 矩形车身轮廓在窄弯中过于保守 | 从官方 URDF 全部碰撞网格测量收臂轮廓，使用包住真实车身并留余量的八边形；未缩放车模 |
| 有转向指令却几乎不转 | 用里程计角速度进行有界比例、积分修正；输出不超过0.65弧度/秒，停止或保护触发时清零积分 |
| DWA在窄弯到点转向失败 | 按赛事教程改用TEB，并给第五弯增加直行到位点 |
| QR附近通用轨迹反复转身 | QR以低速精确进入；退出改为有地图碰撞检查的固定直线倒车 |
| 同一避障间距不适合全部阶段 | 普通窄通道期望间距0.02米；穿桶、物块、返程用0.08米；这不是实际净空保证 |
| 开阔过渡点因厘米级超调卡住 | 锥桶出口、物块前使用5厘米到位容差；其他过渡点通常3厘米 |
| 返程目标与较大避障间距冲突 | 目标移到通道内更宽松的 `(-0.70,1.20)` |
| 终点规划和预计轨迹靠近前墙 | 低速直线停车，目标为 `(-0.25,2.20)`；以完整车身入框和停稳验收 |

直线控制最大速度0.08米/秒。它检查未来约1秒、截至预计停车位置并留少量制动余量的车身范围；车身多边形与障碍方格采用精确相交检查，避免用外接圆近似方格造成误阻塞。障碍、未知格和地图越界都会阻止继续平移。QR退出到位容差3厘米，终点直线停车容差1.5厘米，最终仍按实际车身入框检查。局部地图持续发送完整更新。数据过期、偏航过大、无进展或超时均会失败停车。

TEB的代价地图碰撞检查、完整车身轮廓、姿态保护一直保留。保护在约3°倾斜时暂停，严重倾斜锁定故障。阶段通常最多90秒，总运行保护默认540秒；这些开发保护不替代裁判判定。
